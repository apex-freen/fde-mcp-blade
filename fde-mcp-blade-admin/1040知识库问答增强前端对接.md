## 一、这个功能是什么（前端要知道的背景）

本系统**不做问答机器人、不生成答案** —— 生成答案由客户自己的智能体（Claude / Cursor / Dify / 自研）负责。
我们只负责两件事：

| 块 | 干什么 | 用户能感知到什么 |
|---|---|---|
| **A 检索侧增强** | 让检索**召回得准、排得对**，并且**知道自己不确定** | 检索结果更靠谱；没相关内容的查询不再硬凑 5 条噪声 |
| **B 问答自检** | 用「探针问题」验证**每篇文档问得出来吗** | 文档"放进去了却搜不到"时，页面能直接标红告警 |

两块都挂在既有页面上，**不新增菜单**。

## 三、A 检索侧增强的接口

### 3.1 检索设置（读 / 写）

```
GET  /prod-api/biz/gis_vector/kb_settings
POST /prod-api/biz/gis_vector/kb_settings/save
```

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `min_score` | number | `0.45` | 相似度低于此值的命中**直接丢弃**。调高 = 更严格（可能搜不到），调低 = 更宽松（噪声多） |
| `low_conf_score` | number | `0.55` | Top1 低于此值即视为"置信度低" |
| `hybrid_weight` | number | `0.30` | 关键词分权重（0~1）。`0` = 退回纯向量检索 |
| `candidate_factor` | number | `3` | 先按 `top_k × 该值` 召回候选再重排，一般不用改 |

- 入参校验：4 个值都必须是数字；`hybrid_weight` 限 0~1；其余 3 个限 0~1（`candidate_factor` 限 1~10）。
- 保存后**立即生效**（下次检索就用新值），返回 `data: null`。

### 3.2 别名表

| # | 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|---|
| 1 | GET | `/prod-api/biz/gis_vector/alias/list` | — | `data: GisKbAlias[]`（**含停用的**，前端据此展示状态） |
| 2 | POST | `/prod-api/biz/gis_vector/alias/save` | `{alias_id?, alias, canonical, status?}` | `data: {alias_id}` |
| 3 | POST | `/prod-api/biz/gis_vector/alias/delete` | `{alias_id}` | `data: null` |

`GisKbAlias` 字段：`alias_id`(number)、`alias`(string，**用户可能说的词**，如「打码」)、`canonical`(string，**文档里实际用的词**，如「脱敏」)、`status`(`"0"` 启用 / `"1"` 停用)。

- `alias` / `canonical` 均必填、≤64 字符；同一对重复会被拒绝（唯一键）。
- **`status` 可选**，只接受 `"0"` / `"1"`；**不传或传空串 = 不改**（新增时默认 `"0"` 启用，编辑时保持原值）。
  - 所以「停用 / 恢复」按钮：**提交时带上 `status` 即可**，`alias` 与 `canonical` 原样回传。
  - 传别的值（如 `"2"`、`true`）后端会返回 400，别用布尔。
- **停用的别名不参与检索扩展**，但仍会出现在 `alias/list` 里（否则前端没法恢复）。
- 规则：**检索时只要 query 里出现启用中的 `alias`，系统就把 `canonical` 一起送进向量检索**（只影响召回，不改原始 query）。


### 3.3 页面上的「检索试用」—— ⚠️ 破坏性变更（前端需同步调整）

`POST /prod-api/biz/gis_vector/search` 的返回体**由数组改成了对象**：

| | 变更前 | 变更后 |
|---|---|---|
| `data` | `VectorHit[]` | `{ hits: VectorHit[], low_confidence, suggest_no_answer, expanded_query }` |

新返回体字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `hits` | array | 命中列表（原数组内容，**元素结构见下**） |
| `low_confidence` | bool | 本次召回不可靠（结果为空，或 Top1 低于 `low_conf_score`） |
| `suggest_no_answer` | bool | 建议回"知识库没有依据"，当前与 `low_confidence` 同值 |
| `expanded_query` | string | 别名扩展后实际用于检索的 query（未扩展时等于原 query） |

`hits[]` 元素（即原 `VectorHit`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `chunk_id` / `doc_id` / `index_id` | number | 标识 |
| `index_name` | string | 知识库名 |
| `score` | number | **融合后相关度**（`(1-w)*cosine + w*关键词分`）—— 原 `score` 语义由"余弦相似度"变为"相关度" |
| `vec_score` | number | **新增**：原始余弦相似度（排查用） |
| `chunk_no` | number | **新增**：该片段在文档内的序号，展示成「第 N 段」（显示时 +1） |
| `title` / `source_uri` / `text` | string / string? / string | 标题 / 来源 / 片段原文 |

**前端要做的两件事**：

1. 从 `data.hits` 取列表（原来是 `data` 直接就是数组）。
2. 新增两处提示：
   - `low_confidence == true` → 页面顶部给一条**黄色提示**：*「本次结果置信度低，知识库中可能没有相关内容」*；结果为空时也走这条，别再写"知识库没有"这种绝对话术。
   - `expanded_query != 原 query` → 可在结果区显示一行小字：*「已按别名扩展检索：<expanded_query>」*，方便排查。

> 说明：MCP 侧的 `kb_search` 工具同样有低置信与别名扩展，但它是**文本返回**（在文本开头加标注），不是字段，与本接口无关。

### 3.4 权限

`kb_settings` / `alias/*` / `probe/*` **全部仅管理员可用**（后端返回 403）；非管理员看不到该页，无需额外处理。


## 四、B 问答自检的接口

**全部仅管理员可用**，Header 带登录令牌 `Authorization: Bearer <token>`，返回体统一 `AjaxResult`。

| # | 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|---|
| 1 | GET | `/prod-api/biz/gis_vector/probe/list` | query: `index_id?`、`doc_id?` | `data: GisKbProbe[]`（**含停用的**） |
| 2 | POST | `/prod-api/biz/gis_vector/probe/save` | `{probe_id?, index_id, doc_id, question, status?}` | `data: {probe_id}` |
| 3 | POST | `/prod-api/biz/gis_vector/probe/delete` | `{probe_id}` | `data: null` |
| 4 | POST | `/prod-api/biz/gis_vector/probe/run` | `{index_id}` | `data: ProbeRunSummary` |
| 5 | GET | `/prod-api/biz/gis_vector/probe/last_run` | query: `index_id` | `data: ProbeRunSummary \| null` |
| 6 | GET | `/prod-api/biz/gis_vector/probe/results` | query: `run_id`、`only_failed?` | `data: GisKbProbeResult[]` |

### 4.1 `GisKbProbe`（探针题）

| 字段 | 类型 | 说明 |
|---|---|---|
| `probe_id` | number | 探针 ID（新增时不传） |
| `index_id` | number | 所属知识库索引 |
| `doc_id` | number | 期望命中的文档 |
| `question` | string | 探针问题，≤512 字符 |
| `source` | string | `manual` 手写 / `auto` 系统按文档标题自动生成 |
| `status` | string | `"0"` 启用 / `"1"` 停用 |

新增规则：`probe_id` **不传或 0 = 新增**；`question` 必填且去空格后非空；`doc_id` 必须属于 `index_id`。
**`status` 可选**，只接受 `"0"` 启用 / `"1"` 停用；**不传或空串 = 不改**（新增默认启用，编辑保持原值）。
→「停用 / 恢复」按钮：提交时带上 `status`，其余字段原样回传即可；**停用的探针不参与自检**，但仍会出现在 `probe/list` 里。

### 4.2 `ProbeRunSummary`（一次自检的汇总）

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` | number | 批次 ID（拿去查明细） |
| `index_id` | number | 所属索引 |
| `trigger_type` | string | `manual` 手动 / `sync` 同步后 / `rebuild` 重建后 / `schedule` 定时 |
| `total` / `passed` / `failed` | number | 探针总数 / 通过 / 未通过 |
| `doc_total` / `doc_unrecallable` | number | 文档总数 / 不可召回文档数 |
| `elapsed_ms` | number | 耗时（毫秒） |
| `status` | string | `done` / `failed` |
| `operator` | string | 触发人 |
| `created_time` | string | 开始时间 `YYYY-MM-DD HH:mm:ss` |
| `unrecallable_docs` | array | 不可召回清单：`{doc_id, title, hit_rate}`，`hit_rate` 是字符串如 `"0/1"`。**口径**：有手写题只看手写题，只有自动题才用自动题 —— 所以 `hit_rate` 的分母是"判定用的那一组"的题数，可能小于该文档的探针总数 |

### 4.3 `GisKbProbeResult`（逐题明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 明细行 ID |
| `run_id` / `probe_id` | number | 批次 / 探针 |
| `question` | string | 当次实际使用的问题（快照，题目改了这里也不变） |
| `source` | string | 当次探针来源快照：`manual` 手写 / `auto` 自动。**前端可据此在明细里标注"自动题"，也解释了为什么它不计入告警判定** |
| `expect_doc_id` / `expect_title` | number / string | **期望**命中的文档 |
| `hit_doc_id` / `hit_title` | number / string | **Top1 实际命中**的文档（未命中时 `null`） |
| `hit_rank` | number | 期望文档在 Top-5 里的排名，**1 起；未命中 = 0** |
| `top1_score` | number | Top1 分数（0~1），未命中时 `null` |
| `passed` | string | `"1"` 通过 / `"0"` 未通过 |
| `elapsed_ms` | number | 该题耗时（毫秒） |

## 五、状态与交互

| 场景 | 表现 |
|---|---|
| 从未自检（`last_run` 返回 `null`） | 卡片显示「尚未自检」，探针列表只显示题目，判定列显示「—」 |
| 正在自检 | 「立即自检」按钮 loading + 禁用，文案改「自检中…」；**后端是同步执行，可能十几秒，不要按超时处理** |
| 该文档没有手写题 | 文档行标浅色小标「自动题」，提示可补更精确的问题 |
| 全部通过 | 不显示告警条，通过率显示绿色 |
| 文档已删除但探针还在 | 该文档行的探针不计入分母、不参与判定；建议加灰色标「文档已移除」 |
| 检索设置为空值 / 未初始化 | 后端会返回默认值（0.45 / 0.55 / 0.30 / 3），前端照常展示 |

## 六、错误处理

| 后端返回 | 前端表现 |
|---|---|
| 403 `PermissionDenied` | 不展示管理区块（非管理员本来也进不来该页） |
| 400 `探针问题不能为空/过长` | 表单前端拦截（必填 + 512 字符上限），兜底 toast |
| 400 `文档不存在或不属于该知识库` | toast 并刷新探针列表 |
| 400 `已有自检在执行，请稍后` | toast 提示；按钮恢复可点 |
| 400 `别名与正式词都不能为空` | 表单前端拦截 |

## 七、页面文案建议

- 检索设置区块说明：*阈值调高更严格（可能搜不到）、调低更宽松（噪声多）；关键词权重设为 0 即退回纯向量检索。*
- 别名表说明：*用户嘴里的词 ≠ 文档里的词。在这里补上映射，检索时会自动一起搜。*
- 自检卡片说明：*用探针问题验证每篇文档能不能被检索到；不可召回的文档通常意味着文件没放对位置，或索引需要重建。*
- 空态（无探针）：*系统已按文档标题自动生成探针；建议给重要文档补充更精确的问题。*
- 空态（未自检）：*尚未自检，点右侧「立即自检」。*
- 告警条：*⚠️ N 篇文档不可召回 —— 可能是文件未放对目录，或索引未重建。*

## 八、同页相邻按钮（别搞混）

| 按钮 | 接口 | 说明 |
|---|---|---|
| 重新同步 | `POST /prod-api/biz/gis_vector/sync_system` | 扫描 `knowledge_lib/system/` 增量入库；**按内容 hash 幂等 —— 文件内容没改就不会重新切块** |
| **强制重建（重新切块）** | `POST /prod-api/biz/gis_vector/rebuild`，body `{"index_id":1,"force_rechunk":true}` | 删掉该索引的文档与切块 → 重新扫描 → **重新切块并重算向量**。切块算法 / embedding 模型变更后必须用它；不传 `force_rechunk`（或传 `false`）时行为与原来一致 |

- 告警条里的「去强制重建」建议做成**二次确认**（全量重算 embedding，CPU 占用高、耗时较长）。
- **重建成功后后端会自动跑一轮自检**，点完等一会儿刷新自检卡片即可，不用手动再点。
