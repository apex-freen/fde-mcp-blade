# 1065 单据可见性与流程下钻 · 前端对接

> 模块：`gis_biz_object`（业务链路 / 单据）

> 目标读者：前端

## 一、交付范围

**本次前端要做两件事**（都在 **工作台** 顶级菜单下）：

| # | 页面 | 菜单 ID | 路由 | 组件 | 本次要做 |
|---|---|---|---|---|---|
| 1 | **我的单据** | 1079 | `/workspace/biz/index` | `workspace/biz/index` | 补「单据列表」区块 + 4 个入口（见 §四） |
| 2 | **单据时间线** | 1080 | `/workspace/biz/detail/:biz_object_id` | `workspace/biz/detail/index` | 渲染详情 + 时间线行可下钻单次调用 |

说明：
- 两页均**无权限点**（`permission_id = NULL`，登录即可见），菜单无需调整；
- 菜单 1080 保持 `visible='1'`（隐藏）——它靠列表/URL 带参跳转进入，不显示在侧栏，但**路由仍注册、URL 可直接打开**。

---

## 二、反向约束（务必遵守）

1. **列表里出现的每一行都必须能点进详情**：列表与详情用**同一套可见性**，不会出现“列表有、点进去 403/404”。
2. **只读**：本模块没有任何写接口（除作废）；不要依赖 `title` / `owner_id`（后端当前恒为 `null`）。
3. 页面数据来自后端既有接口 + **1 个新接口**（§三 3.7），其余接口签名/出参不变。

## 三、接口契约

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | GET | `/biz/gis_biz_object/summary` | 看板汇总 |
| 2 | GET | `/biz/gis_biz_object` | 单据列表 |
| 3 | GET | `/biz/gis_biz_object/{biz_object_id}` | 单据详情（节点计划 + 时间线） |
| 4 | GET | `/biz/gis_biz_object/stall_alert/list` | 停摆告警列表 |
| 5 | POST | `/biz/gis_biz_object/stall_alert/scan` | 手动触发停摆巡检 |
| 6 | POST | `/biz/gis_biz_object/{biz_object_id}/close` | 单据作废 |
| 7 | GET | `/biz/gis_biz_object/{biz_object_id}/call/{log_id}` | **【本次新增】单次调用详情（下钻）** |

通用约定：
- 分页参数：`page` / `page_size`（默认 1 / 10，`page_size` 按 `[1,100]` 截断）；分页响应 `data = { total, rows }`；
- 时间：出参统一 `YYYY-MM-DD HH:MM:SS`；`begin_time` / `end_time` 入参接受 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM:SS`；
- 字段命名：本模块为 **snake_case**。

### 3.1 看板汇总 `GET /biz/gis_biz_object/summary`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `begin_time` / `end_time` | string | 否 | 按单据开始时间过滤 |
| `stall_days` | int | 否 | 停摆阈值（天），默认 7，范围 1~365 |

```json
{ "code": 200, "msg": "操作成功",
  "data": {
    "begin_time": null, "end_time": null, "stall_days": 7,
    "total_docs": 10, "stalled_total": 1, "cancelled_total": 0,
    "unassigned_calls": 1520,
    "scenes": [
      { "biz_scene": "repair", "scene_name": "设备报修",
        "total": 8, "open_cnt": 2, "in_progress_cnt": 1, "done_cnt": 4,
        "failed_cnt": 1, "cancelled_cnt": 0, "stalled_cnt": 1,
        "avg_actual_minutes": 25.1, "baseline_minutes": 290,
        "compression_rate": 91.34 }
    ] } }
```
> `scenes` 只含**已归单据**的场景；`unassigned_calls`（**真漏归**）单独给出。`compression_rate` 为 `null` 表示基线未采集 → 显示「待接入」，**不要显示 0%**。
> **`unassigned_calls` 口径（1065 收紧）**：= **带了场景却没带单据号**的调用数（`biz_scene IS NOT NULL AND biz_object_id IS NULL`），即"本该归到某条链路、却漏了单号"。与单据无关的通用工具调用（知识库检索、设备/插件发现、技能列表、控制台等）**不再计入**。前端文案建议写「漏归调用（带场景未带单号）」，tooltip：*调用方声明了业务场景，却没传 `_meta["com.agent-plat/biz"].biz_object_id`*。
> **注意**：`summary` / `list` / `stall_alert` 都按**当前登录人可见范围**返回（详见 §六）。

### 3.3 单据详情 `GET /biz/gis_biz_object/{biz_object_id}`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `stall_days` | int | 否 | 停摆阈值（天），默认 7 |

- `:biz_object_id` = 单据号；**不存在或不可见 → `HTTP 400 + code=404`**；
- 时间线最多返回 **500 行**（超出截断，可提示“仅显示前 500 条”）。

```json
{ "code": 200, "msg": "操作成功",
  "data": {
    "doc": { "...同 §3.2 单行结构..." },
    "actual_minutes": 0.1, "baseline_minutes": 290, "compression_rate": 99.97,
    "plan": [
      { "stage": "report", "seq": 1, "name": "报修", "manual_minutes": 5, "hit_count": 2 },
      { "stage": "dispatch", "seq": 2, "name": "派单", "manual_minutes": 10, "hit_count": 0 }
    ],
    "timeline": [
      { "log_id": 783, "created_time": "2026-09-16 02:16:14",
        "user_name": "test", "tool_name": "local_service_call",
        "plugin_name": null, "method_name": "dify.doc.upload",
        "stage": "report", "stage_name": "报修",
        "success": false, "result_code": "-32030", "result_msg": "该操作属于高风险人工授权范围…",
        "error_type": "perm_denied", "elapsed_ms": 3,
        "approval_id": 9, "handover": true,
        "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736" }
    ] } }
```

**时间线渲染要点**
1. `approval_id != null` 或 `handover = true` → 该步进入过人工环节：加「人工审批」标记 + 单号；
2. **同一 `approval_id` 的两行 = 「被拒那次 + 批准后重放那次」**，可合并展示或分两行标同一单号；
3. `stage` 为空 = 未落节点；`stage_name` 为空 = 未配映射；`plan` 与 `timeline` 用 `stage` 关联，`hit_count = 0` 的节点渲染成「未达成（空心）」；
4. `success` 为布尔；失败原因看 `result_msg` / `error_type`。

### 3.6 单据作废 `POST /biz/gis_biz_object/{biz_object_id}/close`

```json
// Request：reason 必填非空
{ "reason": "重复开单" }
// Response
{ "code": 200, "msg": "操作成功", "data": { "biz_object_id": "WO-DEMO-0007", "status": "cancelled" } }
```
> 权限：**能看见该单据即可作废**（普通用户可作废自己建的单；主管可作废本部门成员的单）；不可见 → `404`。

用途：时间线某一行点开，看**这一次调用**的入参/出参/结果。无权限点，登录即可；鉴权 = 单据可见性 + `log_id` 必须属于该单据。

    "error_type": "perm_denied", "elapsed_ms": 26,
    "approval_id": 9, "handover": true,
    "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",

## 四、页面数据组织建议

### 4.1 我的单据页（`workspace/biz/index`）—— 4 个入口

```
[卡片] 单据总数 · 停摆 · 未归单据调用
[场景表格] 场景 | 单据数 | 进行中 | 已完成 | 失败 | 取消 | 停摆 | 平均实际时长 | 人工基线 | 周期压缩率
[单据列表] ← 本次需补：单据号 | 场景 | 状态 | 当前节点 | 开始 | 最近调用 | 调用次数 | 停摆 | [查看]
[停摆清单] = 单据列表 + stalled=true（或告警列表 status=open）
```
入口 1：单据列表行「查看」→ `/workspace/biz/detail/{biz_object_id}`
入口 2：顶部「按单据号直达」输入框 → 同上（可直接跳）
入口 3：停摆清单行 → 同上
入口 4：URL 直达/可分享（`/workspace/biz/detail/{biz_object_id}`）

### 4.2 单据时间线页（`workspace/biz/detail/:biz_object_id`）

```
[头部]  单据号 · 场景名 · 状态 · 当前节点 · 开始/最近调用/结束 · 调用次数 · 停摆标记
[时长]  实际 0.1 分钟 vs 基线 290 分钟 → 压缩 99.97%
[步骤条] report(2) → dispatch(0) → fix(0) → verify(0) → close(0)   ← plan 的 seq + hit_count
[时间线] 02:16:14 报修 · local_service_call · test · ❌ 已拦下（人工审批 #9）· 3ms
         02:16:21 报修 · local_service_call · test · ❌ -32031（人工审批 #9 重放）· 26ms
         → 点击某行：抽屉/弹窗调 §3.7，展示该次调用的入参/出参
```
- 步骤条用 `plan`（`seq` 排序），`hit_count=0` 用空心/灰色；
- 时间线用 `timeline`；`approval_id` 非空加「人工审批」标签；
- 压缩率是**百分数**（0~100）。

## 五、字段字典

**单据行 `BizObjectRow`（列表 / 详情 `doc` 共用）**
`biz_object_id`（单据号，上游传入）· `biz_scene` / `scene_name`（场景编码 / 中文名，未配置为 null）· `title`（恒 null）· `status`（open/in_progress/done/failed/cancelled，上游声明）· `current_stage` / `stage_name`（当前节点 / 中文名）· `owner_id`（恒 null）· `started_time` · `last_call_time` · `ended_time` · `call_count`（调用次数）· `stalled`（1=停摆）· `silent_days`（静默天数）

**场景汇总行 `BizSceneSummaryRow`**
`biz_scene` · `scene_name` · `total` · `open_cnt` · `in_progress_cnt` · `done_cnt` · `failed_cnt` · `cancelled_cnt` · `stalled_cnt` · `avg_actual_minutes` · `baseline_minutes` · `compression_rate`

**节点计划行 `BizStagePlanRow`**
`stage` · `seq`（顺序）· `name` · `manual_minutes`（人工基线，null=未采集）· `hit_count`（该节点已发生调用次数）

**时间线行 `BizTimelineRow`**
`log_id` · `created_time` · `user_name` · `tool_name` · `plugin_name` · `method_name` · `stage` · `stage_name` · `success`(bool) · `result_code` · `result_msg` · `error_type` · `elapsed_ms` · `approval_id` · `handover`(bool) · `trace_id`

**告警行 `BizStallAlertRow`**
`alert_id` · `biz_object_id` · `biz_scene` · `status`(open/resolved) · `stall_days` · `silent_days` · `last_call_time` · `notified` · `notify_note` · `created_time` · `resolved_time`

**单次调用详情（§3.7 新增）**
见 §3.7 示例；核心：`request_params` / `response_body` / `result_code` / `result_msg` / `error_type` / `elapsed_ms` / `approval_id` / `handover`。

## 六、可见性（前端需要知道的唯一变化）

后端把单据可见性从“工作流可见域”改为“**按人**”：

| 身份 | 谁能看到哪些单 |
|---|---|
| 普通用户 | **自己建的单**（`created_by` = 自己） |
| 部门负责人 | 上面 + **本部门成员**建的单 |
| admin | 全部 |

- 工作流（场景）可见性不变（`org` 全员 / `dept` 本部门 / `user` 本人）；
- 因此 `summary` / `list` / `detail` / `stall_alert/list` / `close` 的可见范围**都随当前登录人变化**，前端无需额外过滤，直接渲染后端返回；
- 「我的单据」页在**部门负责人**视角下会比自己建的单多一些，这是预期。

## 七、交互与边界

| # | 项 | 说明 |
|---|---|---|
| 1 | 只读 | 除作废外无写接口；停摆告警只提示，不改单据状态 |
| 2 | 空态 | `summary.scenes=[]`、`list.total=0`、`detail.plan=[]` 需空态文案 |
| 3 | `title` / `owner_id` | 恒 `null`，不要依赖 |
| 4 | `status` | 上游显式声明；不传就一直 `open`，不是 bug |
| 5 | 时间线行数 | 最多 500 行 |
| 6 | 压缩率 | `null` → 显示「待接入」，不要显示 0% |
| 7 | 所有行可点 | 列表里每一行都要能进详情（后端已保证可见性一致） |

## 八、错误语义

| 场景 | HTTP | `body.code` | `msg` |
|---|---|---|---|
| 未带/失效 token | 401 | 401 | 令牌无效 / 令牌已过期 |
| 单据不存在 / 不可见 | 400 | 404 | 请求的资源不存在 |
| `log_id` 不属于该单据 | 400 | 404 | 请求的资源不存在 |
| 查询参数类型错误 | 400 | 400 | 参数解析失败文案 |
| body 缺字段（作废 reason 为空） | 400/422 | — | 校验提示 |
