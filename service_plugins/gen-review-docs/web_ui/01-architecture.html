01 架构说明

系统是什么、部署在哪、数据是否出域。

1. 产品定位

Apex MCP Bridge 是部署在本地边缘设备上的 AI 智能体中控平台：以标准 MCP 协议对外暴露能力，对内收敛管理 MQTT 设备与本地插件服务，并叠加鉴权、授权、审批与审计治理层。

2. 总体架构（四层）

┌─────────────────────────────────────────────────────────┐
│ ① 接入层   MCP Server（/mcp）+ 内置智能体（文字/语音）    │
├─────────────────────────────────────────────────────────┤
│ ② 治理层   五重安全校验 + RBAC + 审批流 + 风险分级 + 审计 │
├─────────────────────────────────────────────────────────┤
│ ③ 执行层   MQTT 设备通道 + 插件引擎（进程隔离）           │
├─────────────────────────────────────────────────────────┤
│ ④ 数据层   本地 MariaDB + 本地日志目录（不依赖云）        │
└─────────────────────────────────────────────────────────┘

3. 五重安全机制

层机制说明
1令牌鉴权MCP 接入需有效令牌，未授权请求拒绝
2权限校验按令牌/用户权限收敛，无授权能力对 AI 不可见
3时效校验令牌有效期与撤销（会话入库可撤销）
4防绕过工具收敛单入口，禁止绕过治理层直调
5频率限制限制调用频率，防滥用

4. 零云依赖（数据不出域）

  • 默认纯本地：设备（MQTT）、服务（插件）、数据库、日志、LLM/ASR/TTS 均可在本地或内网运行；
  • 云端桥接为可选项：远程控制需人工开启，默认关闭；
  • 数据在本地采集、本地处理、本地存储，默认不出内网。

5. 部署形态

项值
部署方式Docker / Docker Compose（多架构：amd64 / arm64）
数据存储本地 MariaDB（容器内 InnoDB）+ 本地日志目录
升级方式镜像升级 + 幂等 DDL 迁移（重启自动补列/建表）
插件支持热更新，无需重启主服务
