08 降级预案

出事怎么办、备份恢复怎么做、RTO/RPO 承诺。

1. 故障场景与降级

故障影响降级策略恢复动作
云端不可达 / 外网中断远程控制不可用本地功能不受影响（纯本地优先）网络恢复后自动重连
LLM 服务不可用智能体对话不可用设备/服务的直接调用仍可用；可切本地/备用 LLM恢复后切回
单个插件异常该插件能力不可用进程隔离，不影响主服务与其他插件重启/重装该插件
数据库不可用写入失败只读降级/重试；不丢已落库数据按 §2 恢复
磁盘写满写入失败清理 logs/、轮转备份、扩容扩容后恢复
主服务崩溃全部不可用容器 restart: unless-stopped 自动拉起查日志定位

2. 备份与恢复

备份范围（最小集）：apex_db + data/{config,uploads,service-plugins} + .env

项说明
方式bash backup.sh backup（热备，不停服）
加密openssl aes-256-cbc -pbkdf2，密钥 ./backups/.backup_key
轮转保留最近 7 份
恢复bash backup.sh restore <备份文件>（二次确认 + 自动预备份）
# 备份
bash backup.sh backup
# 查看
bash backup.sh list
# 恢复
bash backup.sh restore ./backups/apex-backup-YYYYmmdd-HHMMSS.tar.gz.enc
安全提醒：.env 与 .backup_key 必须与备份文件分开保管，否则加密形同虚设。

3. 升级

项说明
方式Docker 镜像升级（docker compose down && docker compose up -d）
数据库迁移幂等 DDL，重启自动补列/建表
插件支持热更新，无需重启主服务
业务影响升级窗口内短暂不可用；建议先备份

4. RTO / RPO 声明

指标承诺值说明
RPO（数据丢失容忍）取决于备份频率（建议每日）热备；上次备份点之后的数据可能丢失
RTO（恢复时间目标）以现场实测为准整机重装恢复流程见下

恢复流程（整机重装）

1. 安装 Docker / Docker Compose
2. 取回：docker-compose.yml、.env、backups/、.backup_key
3. bash backup.sh restore <最近备份>
4. docker compose up -d
5. 校验：登录 + 插件列表 + 历史会话
RTO 待实测：按上述流程在真实环境演练一次并记录耗时，再回填本表（避免拍脑袋数字）。
