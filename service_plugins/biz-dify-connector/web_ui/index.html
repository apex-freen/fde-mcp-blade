就绪。建议先「① 列出数据集」拿到 dataset_id，再做加文档 / 检索 / 问答。

⚠️ 前提条件核对（任一未满足时方法会返回 code -1 并给出原因）

  • Dify 后台（管理员）：已配置好模型与 embedding 向量模型；知识库 / 应用需已发布生效（发布后才开放 API）
  • plugin.json 配置：config.base_url = http://<host>:<port>/v1（由管理员填入；面板本身不带配置）
  • dataset_api_key：从 Dify「知识库 → API 访问」生成，用于列数据集 / 建数据集 / 加文档 / 检索
  • app_api_key：从 Dify「应用 → API 访问」生成，用于 dify.chat.ask（可选，缺省取 config.app_api_key，也可在面板里用 api_key 临时覆盖）
  • 文档索引是异步的：刚 add_text / upload 完的文档状态为 pending，需稍候自动转为 completed / available 后再 retrieve（embedding 未配置时永远无法完成）
  • 上传文件（dify.doc.upload）：仅限管理员授权使用，且文件必须已存在于 Dify 宿主机本地（file_path 为宿主机绝对路径）

① 知识库：列表 / 创建（dify.dataset.*）

「列出」返回每个数据集的 dataset_id / 名称 / 文档数，把 dataset_id 复制到下方②③去使用；新建的知识库本身不含数据，需再 add_text / upload 加文档，且依赖后台已配 embedding。

④ 应用问答（dify.chat.ask）

返回 data 含 answer（回答文本）与 conversation_id（会话 ID）。多轮对话：把上次的 conversation_id 粘回输入框再提问即可延续上下文。调用的应用须已发布、已配好模型且（若是知识库问答应用）已关联目标知识库。

② 文档写入：按文本 / 按文件（dify.doc.*）

文本类内容（说明、规范、FAQ、纪要）推荐 add_text；需保留原始格式（pdf/docx/md 等）时用 upload。 upload 读取的是 宿主机本地路径（不是本浏览器所在机器），仅管理员授权使用；文件不存在 / 不可读会明确报错。 两者都由 Dify 异步切块 + embedding 索引：刚提交完文档状态为 pending，稍候转 available 后才可被 ③ 检索到。

③ 知识库检索（dify.dataset.retrieve）

返回 data.records[]，每条含 content（片段文本）/ score（相关度）/ document_name（来源文档名）/ metadata，详见下方结果区 JSON。 检索前请确认该知识库文档已完成索引（状态非 pending）；score 为 0~1，越接近 1 相关度越高。
